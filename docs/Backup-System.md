Система резервного копирования VanillaBase предназначена для сохранения и восстановления состояния локального сервера во время разработки и тестирования.

Текущая реализация рассчитана на **Windows** и использует `.bat`-скрипты. Перед созданием резервной копии или восстановлением сервер должен быть полностью остановлен.
## Структура

```text
VanillaBase/
├── backups/
├── scripts/
│   ├── start.bat
│   ├── backup.bat
│   ├── restore.bat
│   └── restore_cancellation.bat
└── server/
```

### `backup.bat`

Создаёт ZIP-архив текущего содержимого `server/`:

```text
VanillaBase_<timestamp>.zip
```

В `backups/` хранится максимум **3 обычных резервных копии**. После успешного создания новой копии более старые автоматически удаляются.

### `restore.bat`

Восстанавливает `server/` из выбранного `VanillaBase_*.zip`.

Перед восстановлением текущее состояние сервера автоматически сохраняется как:

```text
PRE_RESTORE_<timestamp>.zip
```

Это позволяет отменить последнее восстановление. Одновременно хранится максимум **1 PRE_RESTORE**.

Папка `server/` при восстановлении не удаляется и не переименовывается — заменяется только её содержимое.

### `restore_cancellation.bat`

Отменяет последнее восстановление, используя существующий `PRE_RESTORE_*.zip`.

После успешного возврата к предыдущему состоянию `PRE_RESTORE` удаляется.

Таким образом, `PRE_RESTORE` является одноразовой точкой **Undo** для последней операции восстановления, а не частью основной истории резервных копий.

## Схема работы

```text
backup
  ↓
VanillaBase_<timestamp>.zip
  ↓
хранятся последние 3 копии


restore
  ↓
текущее состояние → PRE_RESTORE
  ↓
выбранный backup → server/


restore_cancellation
  ↓
PRE_RESTORE → server/
  ↓
PRE_RESTORE удаляется
```

## Ограничения текущей версии

Система предназначена для локального этапа разработки VanillaBase:
- сервер должен быть остановлен перед операциями;
- скрипты рассчитаны на Windows;
- резервные копии хранятся локально;
- автоматическое создание резервных копий пока не используется.

После переноса VanillaBase на хостинг система резервного копирования будет адаптирована под окружение сервера, вероятнее всего Linux. Тогда же планируется добавить автоматические резервные копии, отдельную политику их хранения и при необходимости внешнее хранилище.
